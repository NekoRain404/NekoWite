# NekoWite Accessibility

This is the current accessibility matrix for the interactive editor chrome that
matters most: the image property panel, the table actions menu, and the confirm /
conflict dialog. It records deliberate roles, labels, and focus behavior, and the tests
that lock them in.

General principles used throughout:

- All controls are **native** `<button>`, `<input>`, `<select>`, `<textarea>` (or a
  labelled wrapper), so they are keyboard-operable and expose their accessible name to
  assistive tech for free.
- Floating panels and dialogs declare a `role` and an `aria-label` (or point at a
  labelled heading).
- Open dialogs trap focus (`composables/useFocusTrap.ts`): on open, focus moves to the
  first focusable control; Tab / Shift+Tab cycle inside; on close, focus returns to the
  previously focused element.
- `contenteditable` editor chrome (the Milkdown surface) is not a focus-trap boundary.

## 1. Image property panel — `ui/ImagePanel.vue`

| Concern | Implementation |
| --- | --- |
| Panel semantics | `role="dialog"`, `aria-modal="false"` (a floating inspector, not a modal), `aria-label` = "Image properties". |
| Field labels | Each control has a `label[for]` wiring to a unique `id` (`neko-image-alt`, `-title`, `-link`, `-width`, `-align`), so screen readers announce the field name. |
| Keyboard entry | When the panel opens (an image is selected), **focus moves to the Alt field** (`altInput.focus()`), so a keyboard user can start editing immediately. |
| Focus restore | When the panel closes, focus returns to the element that was focused before it opened. |
| Keyboard actions | Restore size / Replace / Delete are native buttons — Tab + Enter/Space. |
| Dismiss | **Escape** clears the image selection and closes the panel. |
| Regression | `flush: 'sync'` on the field watchers so the initial population never dispatches a spurious transaction that would reset the selection and close the panel on open. |

Tests: `ui/ImagePanel.test.ts` (aria + label wiring, focus-on-open, Escape closes).

## 2. Table actions menu — `ui/TableMenu.vue`

| Concern | Implementation |
| --- | --- |
| Menu semantics | `role="toolbar"`, `aria-label` = "Table actions". |
| Controls | Each action is a native `<button type="button">` with visible text and a `title` tooltip, so it is keyboard-operable and accessible by name. |
| Visibility | Only shown while the cursor is inside a table cell; hidden when the cursor leaves the table. |
| Actions | Add row below/above, delete row, add column right/left, delete column, toggle header, align left/center/right. |

Tests: `ui/TableMenu.test.ts` (toolbar role + label, per-button name + title, hidden when
cursor is outside a table).

## 3. Confirm / conflict dialog — `components/ConflictDialog.vue`

| Concern | Implementation |
| --- | --- |
| Modal semantics | `role="dialog"`, `aria-modal="true"`, `aria-labelledby` → `#conflict-title`. |
| Focus trap | `useFocusTrap(dialogEl, active)` — on open focus moves to the first button; Tab / Shift+Tab cycle inside; focus restored on close. |
| Keyboard dismiss | **Escape** closes the dialog ("Later"). |
| Actions | Use disk (discard local), Keep local, Later — all native buttons. |

Tests: `components/ConflictDialog.test.ts` (labelled modal, first-control focus on open,
reloadDisk adopts disk content, keepLocal keeps local, Escape closes).

## 4. Shared focus-trap composable — `composables/useFocusTrap.ts`

- Traps Tab inside the container while active.
- Focuses the first focusable on activation (override with `initialFocus: false`).
- Restores the previously focused element on deactivation.
- Its own test: `composables/useFocusTrap.test.ts`.

## Known gaps / follow-ups

- The Milkdown rendered editor surface itself is not fully abstracted for a11y (semantic
  headings are exposed, but live-region announcements for image/table insertion are not).
- The image panel is a non-modal `role="dialog"`; a future enhancement could expose it as a
  `role="region"` with `aria-roledescription` if the app tracks that it stays on-screen
  while editing.
- `aria-live` announcements for history restore / save state are not wired.
