# NekoWite Accessibility

This is the current accessibility matrix for the interactive editor chrome that
matters most: the image property panel, the table actions menu, and the confirm /
conflict dialog. It records deliberate roles, labels, and focus behavior, and the tests
that lock them in.

General principles used throughout:

- All controls are **native** `<button>`, `<input>`, `<select>`, `<textarea>` (or a
  labelled wrapper), so they are keyboard-operable and expose their accessible name to
  assistive tech for free.
- Floating panels and dialogs declare a `role` and an `aria-label` (or point at a
  labelled heading).
- Open dialogs trap focus (`composables/use-focus-trap.ts`): Tab / Shift+Tab cycle inside; on
  close, focus returns to the previously focused element. Where focus lands on open is the
  caller's decision — the trap's default is the first focusable control, and a dialog whose
  first control is destructive overrides it with `initialFocus: false` (see §3).
- `contenteditable` editor chrome (the Milkdown surface) is not a focus-trap boundary.

## 1. Image property panel — `ui/ImagePanel.vue`

| Concern | Implementation |
| --- | --- |
| Panel semantics | `role="dialog"`, `aria-modal="false"` (a floating inspector, not a modal), `aria-label` = "Image properties". |
| Field labels | Each control has a `label[for]` wiring to a unique `id` (`neko-image-alt`, `-title`, `-link`, `-width`, `-height`, `-lock`, `-align`), so screen readers announce the field name. |
| Focus trap | `useFocusTrap(panelEl, visible)` — the same composable the ConflictDialog uses, here with its default `initialFocus`. On open, focus moves to the first focusable field (the Alt input); Tab / Shift+Tab cycle inside the panel while it is open; on close focus returns to the previously focused element (typically the editor). |
| Keyboard actions | Restore size / Replace / Delete are native buttons — Tab + Enter/Space. |
| Dismiss | **Escape** clears the image selection and closes the panel (deactivating the trap and restoring focus). |
| Regression | `flush: 'sync'` on the field watchers in `features/editor/composables/use-image-panel-form.ts` (five watchers) so the initial population never dispatches a spurious transaction that would reset the selection and close the panel on open. |

Tests: `ui/ImagePanel.test.ts` (aria + label wiring, focus-on-open, Tab trap wraps last→first,
focus-restore on Escape, Escape closes). It asserts the ids it names; `neko-image-height` and
`neko-image-lock` were added to that list on 2026-09-22, having previously been the two the
document listed and the test did not check.

## 2. Table actions menu — `ui/TableMenu.vue`

| Concern | Implementation |
| --- | --- |
| Menu semantics | `role="toolbar"`, `aria-label` = "Table actions". |
| Controls | Each action is a native `<button type="button">` with visible text, a `title` tooltip and `aria-label`, so it is keyboard-operable and accessible by name. |
| Visibility | Only shown while the cursor is inside a table cell; hidden when the cursor leaves the table. |
| Keyboard flow | Reached with **Tab** / **Shift+Tab**; navigated with **ArrowLeft / ArrowRight**; activated with **Enter / Space** (native buttons); **Escape** restores focus to the previously focused element (the editor). While focus is in the toolbar, **Tab / Shift+Tab** cycle within it (trapped), so a keyboard user can run every table action without a mouse. |
| Actions | Add row below/above, delete row, add column right/left, delete column, toggle header, align left/center/right. |

Tests: `ui/TableMenu.test.ts` (toolbar role + label, per-button name + title, hidden when
cursor is outside a table, Arrow nav, Tab trap, Escape restore).

## 3. Confirm / conflict dialog — `components/ConflictDialog.vue`

| Concern | Implementation |
| --- | --- |
| Modal semantics | `role="dialog"`, `aria-modal="true"`, `aria-labelledby` → `#conflict-title`. |
| Focus trap | `useFocusTrap(dialogEl, active, { initialFocus: false })` plus a manual `dialogEl.focus()` on the next tick (`components/ConflictDialog.vue`, the `useFocusTrap` call and the `nextTick` focus beside it). **Focus starts on the dialog itself, not on its first control** — that control is 「以磁盘为准」, the destructive answer, and a dialog whose Enter key discards local work by default is the wrong default. Tab / Shift+Tab cycle inside; focus is restored on close. |
| Keyboard dismiss | **Escape** closes the dialog ("Later"). |
| Actions | Use disk (discard local), Keep local, Later — all native buttons, with the confirm slot held by the safe answer. |

Tests: `components/ConflictDialog.test.ts` (labelled modal; "opens with focus on the dialog
itself, not on a destructive button"; "asks the caller for the disk reload instead of performing
it" — the dialog only reports the choice, `reloadDisk` is the caller's; "reports keep local"
/ "reports later" as distinct answers; Escape closes without asking for a reload).

## 4. Shared focus-trap composable — `composables/use-focus-trap.ts`

- Traps Tab inside the container while active.
- Focuses the first focusable on activation (override with `initialFocus: false`, which the
  conflict dialog does — see §3).
- Restores the previously focused element on deactivation.
- Its own test: `composables/use-focus-trap.test.ts`.

## 5. Editor live-region announcements

A single hidden `role="status"` live region (`services/announcer.ts`) announces editor state
changes that a screen-reader user would otherwise miss. It is wired where the state changes
(every call site, checked 2026-09-22):

| State change | Where wired | Message |
| --- | --- | --- |
| Save success | `stores/tab-save.ts` — the save path's own `announce(t('recovery.saved'))` | "Document saved" |
| History restore | `stores/tab-recovery.ts` — the restore path's `announce(t('recovery.restored'))` | "Restored the previous version" |
| Refused save written elsewhere | `stores/refused-save.ts` → `announce(t('tabs.savedAsCopy', { path }))` | "Saved as {path}" |
| Word goal crossed | `features/editor/composables/use-editor-focus.ts` — the word-goal watcher | "Word goal reached: {goal} words" |
| Search result count | `features/editor/controller/editor-search-overlay.ts` — the range-count watcher (only while the find panel is open) | "{count} match(es) found" / "No matches found" (assertive) |
| Trash emptied | `features/sidebar/composables/use-sidebar-trash.ts` — the empty-trash command | "Emptied {n} items" |
| Graph node reached by keyboard | `features/graph/composables/use-graph-canvas.ts` — keyboard node selection | the note's file name (no i18n key: it is the name itself) |
| Chat answer finished | `features/chat/composables/use-chat-send.ts` — the answer-complete branch | "Answer complete" |
| Long image exported | `features/settings/composables/use-export-settings.ts` — the long-image write | "Saved {path} - {width} x {height}, {size}" |

The announcer forces a fresh announcement even for a repeated string (clear then set on a
later tick), and supports a polite (default) vs. assertive (`aria-live="assertive"`) tone.

Tests: `services/announcer.test.ts`, `features/editor/controller/editor-search-overlay.test.ts`,
`features/editor/composables/use-editor-focus.test.ts`.

## Known gaps / follow-ups

- The Milkdown rendered editor surface itself is not fully abstracted for a11y (semantic
  headings are exposed, but live-region announcements for image/table insertion that happens
  in the prose flow are not yet wired — only the property panels and search report here).
- The image panel is a non-modal `role="dialog"`; a future enhancement could expose it as a
  `role="region"` with `aria-roledescription` if the app tracks that it stays on-screen
  while editing.
