# 对照模式滚动同步优化设计

## 目标

让源码/渲染对照模式在连续滚轮、触控板和拖动滚动条时保持跟手、柔和的同步体验，并修复长文档中两侧高度差异导致的回不到顶部或位置被拉回的问题。源码编辑、渲染、关闭自动同步等既有行为保持不变。

## 交互设计

- 用户正在滚动的一侧保持浏览器/CodeMirror 的即时滚动，不延迟输入侧。
- 另一侧通过单一 `requestAnimationFrame` 调度器跟随；连续事件只保留最新目标，不堆积动画。
- 跟随采用短时可打断的缓动（目标约 80–120ms），新输入到来时更新目标，反向滚动或用户直接操作目标侧时立即接管。
- 进入/退出对照模式、分隔条拖动、标题/大纲跳转、到达顶部或底部时取消缓动并直接定位。
- 自动同步关闭时不写入另一侧；重新开启时只执行一次当前比例对齐。

## 定位算法

1. 源码侧滚动事件先换算为当前可见行。
2. 渲染侧根据标题元素的几何位置和解析出的标题行号，定位到对应标题；标题间无可用锚点时退回滚动比例。
3. 渲染侧滚动反向执行同样的映射：取当前视口顶部之前最近的标题，将其行号作为源码目标；没有标题时使用比例。
4. 所有目标值都按各自滚动范围钳制到 `[0, scrollHeight - clientHeight]`，内容高度变化后重新计算，不复用旧范围。

## 实现边界

- 将同步状态（来源、目标、动画帧、抑制标记）集中在编辑器滚动同步控制器，避免通过 Pinia watcher 往返触发反馈回路。
- 保留现有 `EditorPane` 的公开接口，避免影响大纲、搜索、工具栏和插件调用方。
- 不使用全局 `scroll-behavior: smooth`，避免持续滚轮时浏览器反复取消动画造成拖滞。
- 组件卸载、模式切换和窗口失焦时取消待处理的帧和动画。

## 错误与降级

- 任一滚动容器尚未布局或没有可滚动范围时不执行写入。
- 标题解析或元素数量不一致时使用比例定位，不抛出异常。
- `prefers-reduced-motion: reduce` 时关闭缓动，使用即时跟随。

## 测试

- 单元测试验证连续滚动事件在一帧内合并、目标更新不会累积动画、程序滚动不会反馈回源侧。
- 测试有标题和无标题文档的双向锚点映射及边界钳制。
- 组件测试覆盖长文档从底部回到顶部、内容高度不等时仍能到达顶部，以及关闭自动同步时两侧独立滚动。
- 运行 desktop/editor-core 的相关 Vitest、类型检查、lint 和 production build。
