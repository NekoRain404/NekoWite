# NekoWite README Design

## Goal

将 README 从开发手册改为面向 GitHub 访客的现代产品介绍，同时保留足够的安装、开发和插件入口。

## Audience

以想要使用 NekoWite 的写作者、研究者和知识工作者为主；开发者作为第二受众。

## Information Architecture

1. 品牌标题、简短定位、项目徽章和导航链接。
2. 产品价值说明：Markdown/MDX 的可控性与 Word 式编辑体验的结合。
3. 真实应用截图或演示图，作为首屏视觉锚点。
4. 核心能力分区：所见即所得编辑、AI 辅助、数学与引用、文件与历史、插件扩展。
5. 适用场景和产品特性摘要，避免堆砌版本号式功能清单。
6. 快速开始：安装依赖、开发模式、Tauri 桌面模式。
7. 技术栈与项目状态。
8. 开发者入口：测试、构建、目录结构、插件最小示例链接或折叠说明。
9. 安全边界、已知限制、路线图、贡献和许可证。

## Tone And Visuals

- 中文为主，短段落、明确小标题，避免“开发手册”口吻。
- 使用表格、徽章和截图增强扫描性，但不使用夸张营销承诺。
- 只描述仓库中已经存在或明确标注为规划中的能力。
- 截图优先使用项目真实 UI；无法稳定生成时，README 应明确说明当前没有随仓库提供截图，不伪造产品图。

## Accuracy Constraints

- 不再声称与当前测试数量不一致的“全绿”状态。
- 插件无真正 webview/worker 沙箱这一限制必须保留并突出说明。
- 开发命令以根目录 `package.json` 和 CI 实际配置为准。
- README 重写不修改应用代码或构建配置。
