# NekoWite 开发文档

> 目标：构建一款本地优先、Markdown/MDX 保真、编辑体验接近现代文字处理器的专业文档编辑器。

本文结合当前代码结构、已完成优化和前期审计结果，作为后续功能开发、性能治理、安全加固和版本发布的统一依据。

---

## 1. 产品定位

NekoWite 面向：

- 长文作者和技术写作者
- 研究人员与知识工作者
- 需要数学公式、引用、表格和图片的用户
- 需要本地文件控制权的 Markdown/MDX 用户
- 希望通过插件扩展工作流的开发者

核心承诺：

1. 文档文件始终由用户拥有。
2. Markdown/MDX 源码不能被编辑器静默破坏。
3. 可视化编辑必须与源码编辑互相兼容。
4. 大型文档库中仍保持可接受的启动、搜索和编辑性能。
5. 插件和 AI 功能不能突破应用安全边界。
6. 所有重要数据操作都可恢复、可追溯。

---

## 2. 当前技术架构

apps/desktop
- Vue 3 用户界面
- Pinia 状态管理
- Vite 构建
- CodeMirror 源码编辑器
- Tauri 2 桌面壳

packages/editor-core
- Milkdown / ProseMirror 编辑模型
- Markdown / MDX 解析与序列化
- GFM 表格
- 数学公式
- 图片节点
- HTML / Markdown 导出

packages/plugin-host
- 插件 manifest
- 插件生命周期
- 权限声明
- 完整性校验
- 插件注册表

### 架构原则

- editor-core 不依赖桌面平台 API。
- 文件读写、密钥管理和系统能力必须通过 Tauri Rust 层。
- Vue 层负责交互与状态编排，不直接实现安全策略。
- Markdown/MDX 源码是持久化事实来源。
- ProseMirror 文档模型是编辑状态，不是唯一数据来源。
- 插件 API 必须经过稳定的能力网关。
- 长耗时任务必须异步化，并支持取消和失败恢复。

## 3. 当前状态评估

### 已完成或基本完成

- SourcePane 懒加载，CodeMirror 已移出启动主包。
- KaTeX、MathLive 已从启动 preload 路径移除。
- 插件加载错误结构化。
- 插件加载并行化，并设置并发上限。
- 插件完整性摘要校验。
- 敏感插件能力显式提示。
- 搜索任务支持 AbortController。
- 文件监听支持去抖和 latest-wins 防旧结果覆盖。
- 图谱布局已进行自适应和异步分块。
- AI 请求增加并发限制。
- 聊天图片增加单张、会话和全局容量限制。
- 生产 CSP 已从 null 改为明确策略。
- Gemini API key 改用请求头传递。
- Base URL 增加协议和 host 校验。
- 图片支持粘贴、拖放、保存、宽度调整和对齐。
- 表格支持插入、编辑、GFM 解析和序列化。
- TypeScript、Rust、lint、单元测试、E2E 和生产构建已有较完整基础。

### 仍未达到专业产品要求

#### P0：必须优先处理

1. 插件在权限和完整性验证前已经执行顶层代码。
2. 插件与主窗口共享 JavaScript 上下文。assertPermission 不是 Tauri IPC 的安全边界。
3. Rust 文件命令信任前端传入的 vault_root。必须由 Rust 保存并校验当前已打开 vault。
4. 高权限 IPC 可能被同窗口脚本调用。文件系统、密钥和 AI key 需要统一网关控制。
5. 主密码保护不是真正的启动解锁机制。
6. 生产 CSP 与 import(blobUrl) 插件机制存在冲突。

#### P1：影响核心可信度

1. 搜索可能漏掉正文后半部分的匹配。
2. 导出到 vault 外部路径的 UI 与 Rust 写入限制不闭环。
3. 图片导入采用前端 Base64，再由 Rust 解码，存在较高内存峰值。
4. 大型 vault 存在硬截断。
5. 图谱文件变化、链接变化和索引更新需要补充真实场景验证。
6. 链接解析需要覆盖绝对路径、同名文件、同名目录和 ../ 相对路径。

#### P2：影响成熟度

- 图片拖动每次 pointermove 都写入 undo 历史。
- 图片缺少完整属性面板、替换、恢复原尺寸和无障碍操作。
- 表格固定插入 3×3。
- 表格缺少行列增删、列宽调整、单元格合并、多选和复制粘贴。
- 缺少 Excel/CSV 粘贴。
- 宽表格和移动端横向布局不足。
- 尚无正式性能基准。
- 测试仍有非致命警告，且缺少真实 Tauri 环境覆盖。
- 插件生态文档、版本兼容策略和 API 稳定性规则不足。

## 4. 产品功能标准

### 4.1 文档模型

文档必须支持：

- YAML frontmatter
- Markdown 标准语法
- GFM 表格、任务列表、删除线
- $...$ 和 $$...$$ 数学公式
- 图片和附件
- 内部链接、外部链接、锚点链接
- MDX JSX 组件
- 未知 MDX 节点保留
- 源码与可视化视图往返编辑

### 4.2 MDX 保真原则

必须满足：MDX 源码 → 解析 → 编辑器模型 → 修改 → 序列化结果 → 再解析 → 语义结构保持一致。

要求：

- 不删除未知 JSX。
- 不重排用户未修改的代码。
- 不丢失 frontmatter。
- 不破坏表达式、导入语句和组件属性。
- 序列化必须尽量保持原始格式。
- 对无法可视化编辑的节点显示源码占位，而不是静默删除。
- 每次编辑都可以通过撤销恢复。

必须建立 round-trip 测试集：普通 Markdown、嵌套 JSX、JSX 属性表达式、import/export、表格中嵌入组件、图片属性、数学公式、混合中文/英文/特殊字符、不完整或非法 MDX。

## 5. 图片编辑开发要求

### 目标能力

1. 图片选中态和明确 resize handle。
2. 属性面板：alt、title、链接、宽度、对齐、原始尺寸、恢复尺寸、替换图片、删除图片。
3. 键盘调整宽度。
4. 等比例缩放和比例锁定。
5. 撤销历史合并：一次拖动只产生一个 undo 步骤。
6. 大图片导入前检查大小和格式。
7. 采用文件路径或流式 API，避免 Base64 全量复制。
8. 明确 SVG 是否允许，以及是否进行脚本和外链限制。
9. 加载失败时显示可恢复错误，而不是空白区域。
10. 支持 alt 文本和屏幕阅读器。

## 6. 表格编辑开发要求

### 第一阶段

- 自定义行数和列数插入。
- 添加/删除行、添加/删除列。
- Tab 到最后一个单元格自动新增行。
- 列宽拖动。
- 表头切换。
- 左中右对齐。
- 单元格复制、剪切、粘贴。
- 多单元格选区。

### 第二阶段

- Excel/CSV 粘贴。
- 单元格合并与拆分。
- 行列拖动排序。
- 表格转置。
- 空行、空列清理。
- 大表格虚拟化或分块渲染。
- 表格 Markdown 和 HTML 双向保真。

### 暂不建议默认实现

复杂公式系统、类似电子表格的完整计算引擎、自动改变用户 Markdown 结构的排序功能。

## 7. 搜索、索引与图谱

### 搜索目标

必须实现真正的全文检索：文件名、路径、标题、标签、frontmatter、正文全文、MDX 文本内容、附件元数据。

### 图谱目标

- 支持全量 vault，而非固定前 200 篇。
- 增量更新节点和边。
- 正确处理相对路径、绝对路径和同名文件。
- 显示断链和孤立节点。
- 大图谱布局放入 Worker。
- 缩放、主题和窗口变化不重复计算布局。
- 支持按目录、标签和链接类型筛选。

---

## 8. 安全开发要求

### 插件安全

最终目标：插件源码 → 静态解析 → manifest/签名/权限确认 → 隔离 Worker 或独立进程 → 能力网关 → 最小权限 IPC。

禁止：在授权前动态执行插件代码、插件直接访问 Tauri invoke、插件自行决定 vault 根目录、插件读取 API key 明文、仅通过前端数组判断权限。

### 密钥安全

- 使用 Argon2id、scrypt 或 PBKDF2 等适当 KDF。
- 每个 vault 使用随机 salt。
- 密钥存储优先使用系统 Keychain/Credential Manager。
- 启动时必须明确锁定和解锁状态。
- 日志中禁止出现 token、API key 和解密材料。
- 更换主密码必须支持密钥轮换。
- 错误信息不得泄露密钥存在性。

## 9. 性能预算

| 指标 | 目标 |
|---|---|
| 冷启动到可编辑 | 中端设备 ≤ 2 秒 |
| 首次输入响应 | P95 ≤ 50ms |
| 普通文档打开 | ≤ 300ms |
| 1 万文件搜索 | 首次索引后 P95 ≤ 300ms |
| 文件变更到索引完成 | P95 ≤ 1 秒 |
| 1 万节点图谱 | 不阻塞输入，布局异步 |
| 10MB 图片插入 | 不发生明显 UI 冻结 |
| 500×30 表格编辑 | 输入响应 P95 ≤ 100ms |
| 启动主 JS gzip | 持续监控，禁止无理由增长 |

## 12. 推荐开发里程碑

### M1：安全和数据可信度
### M2：MDX 保真编辑
### M3：图片和表格专业编辑
### M4：全文索引和知识网络
### M5：大型 vault 性能
### M6：产品成熟度

## 13. Definition of Done

一个功能只有同时满足以下条件才算完成：功能在 UI 中形成完整闭环、正常/失败/取消路径均有处理、不破坏已有 Markdown/MDX、有单元测试或 E2E 测试、关键场景有跨平台验证、有性能数据或明确说明性能无影响、涉及权限和文件时有安全测试、错误信息可理解且可恢复、文档/变更记录/迁移说明已更新、类型检查/lint/测试/构建全部通过。

## 14. 当前版本结论

后续开发顺序应固定为：安全边界 → MDX 保真 → 图片/表格结构编辑 → 全文索引与图谱 → 大型 vault 性能 → 恢复、无障碍和插件生态。在 M1 和 M2 完成前，不建议将项目宣传为稳定版或允许安装来源不明的第三方插件。
